# SR110U V223 Hardware programming

Install the matching ASL3 `sa818` update with `--protocol sr110u-v223` and
`advanced` support before using this UI revision. The backend checks the real
CLI version response before programming; it does not infer a board model from
USB adapter IDs or saved selections.

The verified `110U-V223` dialect uses seven group fields and two-digit CTCSS
codes. Newer SR110U firmware may use different field ordering, so unknown
versions are rejected. Standard SA818 programming remains the default for
other modules. Missing version support alone is not a connection failure.

V223 supports channel, CTCSS/none and volume commands. Unsupported DCS, tail,
pre/de-emphasis and SA818 high/low-pass filter controls are disabled or skipped
and listed in the result. A saved file is intent, not a readout of the radio.

Advanced settings are opt-in: busy-channel lock, high/low power, companding,
microphone sensitivity, transmit timeout, VOX and automatic power saving.
With opt-in off, the legacy group uses busy-lock on/high power/companding off;
other advanced settings are untouched. Scrambling has no control and is
forced off in the microphone command. VOX is off before advanced programming,
and enabled last only if explicitly requested; it requires power saving off.

Validation includes simulated protocol/API tests and live command acknowledgments
on V223. Standard SA818S V1.2 was also programmed and its channel fields checked
using its supported readback query. V223 does not provide that readback through
the verified protocol. VOX-on behavior, power output, microphone gain, timeout
accuracy, power-cycle persistence and RF effects have not been measured.
A failure stops later writes but cannot undo settings already accepted.

Changing an existing TX tone no longer silently enables RX tone. Initial tone
selection when both sides are None retains the existing coupled-selection behavior;
operators can independently set RX to None afterward.
